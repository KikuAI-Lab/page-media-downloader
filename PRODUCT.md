# Product

## Register

product

## Users

People using Chrome or Brave who want to save media already exposed by the page they are viewing. They may not understand browser media terminology and should be able to complete the primary task in seconds.

## Product Purpose

Find photos, direct videos, and direct audio on the current page, make video and currently playing audio especially easy to spot, and download only the items the user chooses. Success means the user can open the popup, recognize what was found, and start the correct download without interpreting technical controls.

## Brand Personality

Direct, calm, trustworthy. The interface should feel like a small native browser utility, not a social-network-specific downloader or a developer console.

## Anti-references

- Instagram-specific gradients or camera branding in the generic product.
- Several equally prominent actions competing on the first screen.
- Technical terms such as lazy-load, MV3, HLS, or DASH in the primary workflow.
- Empty metadata panels, permanently disabled controls, or decorative status chrome.

## Design Principles

- Lead with the media and the next safe action.
- Separate discovery from downloading.
- Keep the result order stable: video, audio, photo.
- Mark currently playing audio in plain language and place it first within the audio group.
- Hide uncommon full-page behavior until the user asks for it.
- Explain limitations in plain language without making them the main interface.

## Accessibility & Inclusion

Target WCAG 2.2 AA contrast. The full popup must work with keyboard navigation, visible focus, labelled selection controls, screen-reader status announcements, and reduced-motion preferences.

## Lifecycle

Live product contract. Update when the popup's audience, purpose, or interaction principles change; code and tests remain the implementation truth.
